# SEO-отчёты в админке

Экран доступен авторизованным пользователям с ролью `admin` или `editor`:

`/admin/seo`

Он показывает реальные данные Google Search Console и Яндекс Вебмастера:

- клики, показы, CTR и среднюю позицию;
- динамику позиции;
- топ запросов и отдельный рейтинг посадочных страниц;
- географию показов Google по странам;
- рост и снижение позиций;
- фильтры Google за 30, 90, 180 и 365 дней;
- отчёты Яндекса за 30, 90, 180 и 365 дней после безопасного включения накопления истории;
- фильтр по устройству и поиск по запросу;
- экспорт CSV.

Демо-данные не используются. Если источник не подключён или данных нет,
интерфейс показывает честный статус.

## Цели и конверсии Яндекс Метрики

Вкладка целей показывает данные по всем каналам, а не только из поисковой
выдачи: достижения целей, целевые визиты и прямую конверсию. Достижения — это
число срабатываний цели, поэтому несколько действий в одном визите считаются
отдельно; целевые визиты показывают количество визитов, в которых цель была
достигнута хотя бы один раз.

Для вкладки нужны server-only переменные:

```dotenv
YANDEX_METRIKA_OAUTH_TOKEN=
YANDEX_METRIKA_COUNTER_ID=
```

OAuth-токен должен иметь только право чтения `metrika:read`.
`YANDEX_METRIKA_COUNTER_ID` может быть пустым, если задан
`NEXT_PUBLIC_YANDEX_METRIKA_ID`. Ручное обновление во вкладке обходит
15-минутный серверный кэш и запрашивает свежие данные.

## Google Search Console

Переменные:

```dotenv
GOOGLE_SEARCH_CONSOLE_CLIENT_EMAIL=
GOOGLE_SEARCH_CONSOLE_PRIVATE_KEY=
GOOGLE_SEARCH_CONSOLE_SITE_URL=
```

Порядок подключения:

1. Создать service account в Google Cloud и включить Search Console API.
2. Добавить email service account в Search Console как пользователя
   подтверждённого ресурса с правом чтения.
3. В `GOOGLE_SEARCH_CONSOLE_SITE_URL` указать точный идентификатор ресурса:
   `sc-domain:example.ru` либо полный URL-prefix.
4. Закрытый ключ хранить только в Vercel Environment Variables. Переносы строк
   можно передать как `\n`; приложение восстановит PEM-формат.

До покупки отдельного домена ресурсом этого проекта является
`https://kbparus-metal-storage.vercel.app/`. `kbparus.ru` и
`линииокраски.рф` относятся к другим сайтам бренда и намеренно блокируются
как источники canonical и как свойство Search Console для этого проекта.
Корпоративный адрес `info@kbparus.ru` при этом остаётся допустимым контактом.

Search Console показывает среднюю позицию по фактическим показам, а не
гарантированное место для произвольного запроса. Редкие запросы могут быть
скрыты самим Google.

Сводные клики, показы, CTR и график запрашиваются отдельно на уровне всего
ресурса. Запросы, страницы, связка «запрос → страница» и страны формируются
отдельными запросами. Детализация запросов может быть неполной из-за правил
конфиденциальности Google; рейтинг страниц при этом запрашивается отдельно
и не строится только по раскрытым поисковым фразам.
Сравнение для периода 365 дней отключено: live-истории Search Console
недостаточно для двух полных лет.

## Яндекс Вебмастер

Переменные:

```dotenv
YANDEX_WEBMASTER_OAUTH_TOKEN=
YANDEX_WEBMASTER_USER_ID=
YANDEX_WEBMASTER_HOST_ID=
YANDEX_WEBMASTER_REGION_IDS=
SEO_YANDEX_HISTORY_ENABLED=false
CRON_SECRET=
```

`YANDEX_WEBMASTER_REGION_IDS` — необязательный список ID регионов через
запятую. OAuth-токен и идентификаторы пользователя/сайта берутся из Яндекс
Вебмастера API.

Live API Яндекса отдаёт статистику только за последние 14 дней. Для накопления собственной истории в `vercel.json` настроен ежедневный production-cron `/api/cron/seo/yandex` на `03:15 UTC` (`06:15` по Москве). Vercel запускает расписание только на production-deployment и передаёт `CRON_SECRET` в заголовке `Authorization: Bearer ...`.

Каждый успешный запуск обновляет последние 14 завершённых дней по московскому времени для всех устройств и хранит 400 дней. Поэтому периоды 30, 90, 180 и 365 дней заполняются реальными данными постепенно. Первый запуск обычно добавляет не более 14 дней; интерфейс показывает фактическое покрытие, а не подменяет отсутствующую историю.

Безопасный порядок включения:

1. Создать точку восстановления/ветку production-базы и проверить восстановление.
2. Выполнить read-only аудит миграций, затем применить `migrations/20260728_001500_seo_yandex_history.ts` через контролируемую команду `npm run cms:migrate:apply` с `DATABASE_URL_UNPOOLED`.
3. Подтвердить запись миграции и наличие таблиц `seo_yandex_history`, `seo_yandex_sync_days`, `seo_yandex_collection_runs`.
4. Добавить в Vercel Production отдельный случайный `CRON_SECRET` и установить `SEO_YANDEX_HISTORY_ENABLED=true`.
5. Выпустить production-deployment: только после него Vercel зарегистрирует расписание.
6. Проверить первый защищённый запуск и новую запись в `seo_yandex_collection_runs` со статусом `success` или разобрать конкретную ошибку при `partial`/`failed`.

До применения миграции флаг остаётся выключенным. После успешной проверки
`CRON_SECRET` маршрут безопасно отвечает `200` со статусом `skipped` и причиной
`disabled`, не открывает CMS и не создаёт ежедневный шум ошибок. Повторные
запуски после включения идемпотентны, параллельный сбор блокируется PostgreSQL
advisory lock.

## Верификация сайта

Необязательные переменные:

```dotenv
GOOGLE_SITE_VERIFICATION=
YANDEX_SITE_VERIFICATION=
```

В них записывается только verification token без HTML-тега целиком.

## Безопасность

- API отчётов недоступен без активной Payload-сессии.
- Доступ разрешён только ролям `admin` и `editor`.
- Ответы не кэшируются публично.
- Повторные одинаковые отчёты используют закрытый серверный кэш на 15 минут.
- OAuth-токены и приватные ключи не передаются в браузер.
- Секреты нельзя добавлять в Git, скриншоты или клиентские переменные `NEXT_PUBLIC_*`.

## Ограничение точности

Отсутствие показов не означает позицию `100+`. Для ежедневной проверки
произвольного списка запросов по конкретному региону и устройству нужен
лицензированный rank-tracker. Скрапинг поисковой выдачи в проект не встроен.
