# Производительность изображений категорий

Дата: 27 июля 2026  
Рабочая ветка: `codex/mobile-responsive-20260726`

## Подтвержденная причина

- 17 исходных изображений категорий весили 27,71 МБ.
- 15 файлов были PNG по 1,03–2,52 МБ без необходимости в прозрачности.
- Первые две карточки каталога ошибочно имели высокий приоритет, хотя каталог расположен ниже hero.
- Отсутствующие CMS sizes заменялись исходным PNG, после чего Next.js выполнял холодную AVIF-конвертацию на лету.
- Изображения калькулятора, кейсов и баннеров без `loading="lazy"` создавали 11,86 МБ ранних preload-запросов и конкурировали с каталогом.

## Реализованное решение

- Добавлен build-step `images:optimize-catalog`.
- Для каждого исходника генерируются хешированные WebP-варианты 320×240, 640×480 и 960×720.
- Карточки используют прямой responsive `srcset`, `loading="lazy"`, `decoding="async"` и `fetchPriority="low"`.
- Удален высокий приоритет у изображений каталога.
- Исходники остаются доступными для CMS и резервного сценария.
- Для новых Payload-загрузок добавлены размеры `cardSm`, `cardMd`, `cardLg`.
- Новые Blob-файлы получают уникальный суффикс.
- Хешированные WebP отдаются с `Cache-Control: public, max-age=31536000, immutable`.
- Все остальные тяжелые изображения ниже первого экрана переведены на ленивую загрузку.

## Результат

| Набор | Общий вес 17 файлов | Снижение |
|---|---:|---:|
| Исходные изображения | 27,71 МБ | — |
| WebP 320 px | 154,3 КБ | 99,5% |
| WebP 640 px | 436,5 КБ | 98,5% |
| WebP 960 px | 793,2 КБ | 97,2% |

Ранние preload-изображения главной сокращены с 11,86 МБ до 159,8 КБ. В локальной production-сборке карточки больше не используют `/_next/image` для fallback-каталога.
