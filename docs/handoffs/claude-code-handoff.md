## Продуктовые правила

Сайт совмещает каталог и инженерный подбор. Клиент выбирает утверждённые параметры, видит только ориентир `от ... ₽` и передаёт конфигурацию инженеру. Цена не является коммерческим предложением.

- Публичный каталог содержит ровно 17 разделов в порядке `data/storageSystems/excelCatalog.ts`.
- Не расширять каталог без прямого решения владельца продукта.
- Не показывать клиенту Excel, адреса ячеек, внутренние идентификаторы или сокращения исходного файла.
- Тексты интерфейса — на русском, без внутренних технических формулировок.
- Главное визуальное правило: реальные системы хранения и конструктивно достоверные изображения.

## Архитектура

- `app/(site)/` — публичные страницы и metadata.
- `app/(payload)/` — Payload admin и его кастомные компоненты.
- `components/` — публичные React-компоненты.
- `data/storageSystems/` — fallback-каталог, профили калькуляторов и презентационные данные.
- `lib/calculator/` — расчёт, валидация, рекомендации и типы; формулы не размещать в UI.
- `lib/cms/` — адаптеры Payload с fallback на статические данные.
- `lib/leads/` и `app/api/leads/route.ts` — валидация и доставка заявок.
- `payload/` — коллекции, глобалы и структура админки.
- `public/assets/images/` — локальные изображения категорий, товаров и калькулятора.
- `tests/` — Vitest; `e2e/` — Playwright.

## Публичный сайт

- Главная: hero → каталог → калькулятор → доказательства/кейсы → контакты.
- На мобильном каталог показывает две компактные карточки в ряд; на экранах до 350 px — одну.
- `/catalog/[id]` сразу показывает товары, без длинного вводного контента.
- `/catalog/[id]/[productId]` сохраняет название и галерею сверху, затем сразу ведёт к заявке или калькулятору.
- Товар может иметь `pageMode=standard` или `pageMode=calculator`.
- Обычный товар показывает форму заявки. Товар с калькулятором не дублирует форму и использует закреплённый `calculatorProfile`.
- Характеристики, состав подбора и документы находятся ниже формы/калькулятора.

## Калькулятор

- Главная: выбор системы → параметры → результат.
- Товар: профиль уже закреплён, поэтому пользователь сразу попадает в параметры → результат.
- Главная и товары используют один `components/Calculator.tsx` и один расчёт в `lib/calculator/`.
- Длина, ширина, полезная высота, нагрузка, полки и башни выбираются плашками; ползунков нет.
- Для автоматического стеллажа доступны 6–25 полок.
- Compact/Logic: одна башня. Spider/Cross: 2–6 башен.
- Правая сводка крупная, закрепляется при прокрутке и не перехватывает колесо мыши.
- Цена и размеры используют неразрывные пробелы; число и `₽` не переносятся отдельно.
- Опции показываются визуальными карточками с подсказкой по hover/focus.

Точная подтверждённая логика габаритов автоматического стеллажа:

```text
длина системы = 800 + длина рабочей ячейки
ширина системы = 1100 + 2 × ширина рабочей ячейки
высота системы = 1400 + полки × (полезная высота + 60) + 500 × башни
масса без нагрузки = (3500 + 300 × полки) × башни
масса листов = полки × нагрузка × башни
нагрузка на одну опору башни = (3500 + 300 × полки + нагрузка × полки) / 4
```

Для профилей без подтверждённой формулы нельзя придумывать габариты: UI пишет `Уточнит инженер`.

## Изображения опций

Презентационные данные: `data/storageSystems/calculatorOptionPresentation.ts`.

Файлы: `public/assets/images/calculator/options/`.

- загрузочная станция с весами — башня, паллета/лист, измерение массы;
- световое защитное ограждение — передатчик и приёмник у опасной зоны;
- вакуумный захват — траверса и присоски, работающие с листом;
- консольно-поворотный кран — колонна, поворотная стрела, таль и крюк;
- складской учёт — реальная система хранения проекта и экран управления.

Перед заменой изображения пройти критерии `docs/operations/calculator-option-validation.md`. Нельзя использовать красивую, но конструктивно неверную генерацию.

## CMS и админка

- `/admin` — рабочая Payload-панель, не отдельное демо.
- Порядок категорий совпадает с публичным сайтом.
- В товаре явно видны режим страницы и привязанный профиль калькулятора.
- `pageMode=calculator` нельзя сохранить без `calculatorProfile`.
- Контент имеет preview/status/health и ролевой onboarding.
- Контент читается через Payload с безопасным статическим fallback.

После изменений Payload-компонентов запускать `npm run cms:generate-importmap`. Изменения схемы выполняются только миграциями; обычный build не должен самовольно менять production-БД.

## Заявки

`POST /api/leads` получает контакты, город, комментарий, UTM, источник, URL/название/изображение товара и структурированную конфигурацию. Сервер повторно рассчитывает калькулятор и для товарной ссылки подставляет доверенные данные опубликованного товара.

Критическое правило QA: **не отправлять реальные заявки без явного разрешения владельца**. Playwright обязан перехватывать и abort/mock `/api/leads`. Проверять production только GET-запросами (`/`, `/catalog/...`, `/api/health`, `/admin`).

API показывает успех только если лид сохранён/доставлен хотя бы в один реальный канал. При полной недоступности каналов возвращается `503`, а не ложный mock-success.
